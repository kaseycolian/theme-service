Workflow A — Apply the themes to an app

You ask; the agent does the wiring and confirms the choices that matter before changing anything.

"Apply the theme-service to this app" you → Claude (skill)
Locate the source reads machine-local config
Confirm the choices that matter restyle depth? fonts? existing selector? placement?
Vendor CSS + map colors to tokens agent → your app repo
Add a theme picker + persistence all themes selectable
Verify WCAG AA + write tracking log THEME-SERVICE.md
Done — switch themes live nothing else changed

Workflow B — Clone / save / update, with your own storage

Your themes live on your machine and persist with a plain local commit — GitHub is optional. You can still pull upstream updates anytime without losing your themes.

Origin — theme-service clone or fork (once)
Your machine — local clone add your themes → tools/palettes/local.mjs → npm run build-themes → git commit (saved locally ✔, no GitHub required)
npm run update-from-origin fetch + merge, conflict-free — your local.mjs is never touched; nothing auto-deleted
Optional: git push → your own GitHub backup · sync machines · share

Solid = local (works with just local git). Dashed = optional GitHub.
